### Decisions
- Repo root is `D:\HomeworkChecker` (it plays the role of `homework-lamp/` in the spec).
- **All routes live under `/api`.** Vite proxies `/api` and `/socket.io` → one origin, so a single ngrok tunnel covers the phone camera.
- **The backend owns `hint_level`/`attempts`** (per normalized problem string, in the session). The client only sends `action: react | hint | chat`. This is stricter than the spec's "input: attempts, hint_level" and enforces "backend gates reveals".
  - `attempts` += 1 each time a grade finds that problem wrong. On `react`, level = max(level, attempts, 1). On `hint`, level += 1. The cap is 4, and the reveal happens at 4.
  - Answer-leak guard: below level 4, an LLM reply containing the correct answer is replaced by a template.
- **Mock mode** (no `GEMINI_API_KEY`): uploads byte-identical to a sample use its sidecar; other images (live camera) cycle worksheet-1 → worksheet-2. Tutor/report fall back to en/es/vi templates.
- **Error steps:** a rule-based `diagnose()` (no-carry addition, smaller-from-larger subtraction, off-by-one) runs first. The 2nd Gemini call runs only when `has_work` and a key is set. `error_bbox` falls back to `answer_bbox`.
- Added `answer_bbox`, `answered`, `needs_confirmation`, and `fixed_ids` to the `/grade` response beyond the spec (all additive).
- Report numbers and practice problems are computed in Python (SymPy-checked). The LLM only writes the summary sentence.
- Capture trigger = armed (hand seen since last capture) AND no hands AND still ≥1.5 s AND >0.25% of pixels changed vs the last graded frame (160×120 grayscale). If MediaPipe fails to load, motion stands in for hands.
- Sounds are synthesized with WebAudio (no asset files).
- The robot's name is **Lumi**.

## 2026-10-18 — Session 1b: Gemini speed-up

### Measured (worksheet-1, `gemini-3.8-flash`, free tier)
| Call | Thinking | Time | Result |
|---|---|---|---|
| extract | model default | 15.6 s (771 thought tokens) | 6/6 read correctly |
| extract | `low` | 9.9 s (0 thought tokens) | 6/6 read correctly |
| tutor reply | `low` | 4.3 s | sensible level-1 hint, no answer leak |
- The first ">90 s" request could not be reproduced; its cause is unknown (possibly free-tier queueing).
- **Free tier = 20 requests/day per model** for gemini-3.8-flash (from Google's 429 error, quotaId `GenerateRequestsPerDayPerProjectPerModel-FreeTier`). That's only ~2–3 demo run-throughs a day.

### Changes
- `llm.generate_ex()` returns `(result, error)` with error ∈ timeout/quota/error, applies `thinking_level` (default `low`), enforces a timeout (`GEMINI_TIMEOUT`, default 25 s), and logs time and tokens per call (`INFO: gemini <label> …`).
- Extraction thinking is set by `GEMINI_VISION_THINKING` (default `low`). `minimal` is untested.
- The 2nd error-step Gemini call is skipped when rule-based `diagnose()` already explains the mistake.
- `/grade` returns `llm_error`. On error it keeps the previous grade, so hints still work. The frontend speaks "out of thinking power for today" (quota) or "that took too long" (timeout) instead of "I can't read that".
- The frontend shrinks uploads to a 1600 px longest side before sending; smaller images are sent untouched so mock-mode sample matching still works.
- Lumi speaks a short filler ("Let me take a close look…") while Gemini works.
- Fixed: the sleep timer spammed `POST /api/lamp/led?state=off` every 2 s while asleep. It now fires once.
- Key setup: the key belongs in `backend/.env` (gitignored), never `.env.example`.

### Next ideas
- To reduce quota use: a Flash-Lite model for tutor replies, or tutor templates for hint levels 1–2.
- Tune trigger thresholds with real webcam footage; add a "page found" check (paper detection) before capturing.
- Stream TTS sentence by sentence; show `thinking` sooner on slow Gemini responses.
- Confirm-by-voice flow for low-confidence answers ("Is that a 7 or a 1?" → child says "seven").
- Stretch: word problems and fractions; SQLite persistence for sessions.

### Not yet verified

### Decisions
- One turn endpoint with `action` instead of many routes. The client renders `turn.step` and never decides correctness. Wrong action for the current step → the last turn is repeated (the client can always recover). Stale `worksheet_id` → 409 → the client reloads.
- Gate default: Teach mode needs a concept shown in Help mode; "Grown-up: try anyway" forces {carry, off_by_one}.
- Demo problems come from `teach._make(concept)` (same shape), not `practice_for_concept` (it drifted: careful-counting demo of 84 + 99).
- Chips are in the child's voice ("You forgot to carry…"). Correct chip = +½ star, straight to demo.
- Badges for missed / confirmed-OK rows are hidden until found / done, so the page never gives away the answer.
- Keypad keeps a ref to the latest value (two fast taps before a re-render were collapsing into one digit).
- Changing language remounts Teach mode with a fresh worksheet.
- A `.claude/launch.json` in `D:\Techstars` runs this repo's backend/frontend (used for the browser check).
